## 步骤 1 · 裸 LLM 调用（景区客服口径）

**目标**：打通一次 Chat Completions；system = 景区售前助手。

### 环境

`.env`（勿提交）：

```
DEEPSEEK_API_KEY=你的key
```

依赖已有：`openai`、`python-dotenv`。

### 代码：见 `examples/step01_llm/main.py`（已落盘，可回顾）

```python
# 验收：能口述 system/user/assistant/tool；同问两次答案可不同
# 禁止：不得编造未检索到的票价/开放时间；不得承诺下单成功；缺景区名须追问
# 下一步：抽出 Model Adapter

from openai import OpenAI
from dotenv import load_dotenv
import os

load_dotenv()

client = OpenAI(
    api_key=os.environ["DEEPSEEK_API_KEY"],
    base_url="https://api.deepseek.com",
)

messages = [
    {
        "role": "system",
        "content": (
            "你是景区门票售前智能客服助手（教学 Mock）。"
            "只能：理解游玩咨询、追问缺失槽位（景区名/日期/人群）、说明需要查什么。"
            "禁止：编造票价或开放时间；承诺已下单/已退款；在未调用查询工具前给出确定营业数据。"
            "当前还没有工具，若用户问具体票价/开放时间，明确说需要先查景区资料，并追问景区名。"
        ),
    },
    {
        "role": "user",
        "content": "明天想去苏州玩，有什么园子推荐？门票多少钱？",
    },
]

resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=messages,
)

print(resp.choices[0].message.content)
```

```bash

```

## 步骤 2 · Model Adapter

**目标**：业务入口只认 `ModelRequest` / `ModelResult`；换协议 = 换 Adapter，不改售前文案。

### 你要读 / 对照

- 本仓新增：
  - `src/scenic_cs_agent/runtime/model_types.py` — 契约
  - `src/scenic_cs_agent/runtime/deepseek_chat_adapter.py` — Chat Completions（默认）
  - `src/scenic_cs_agent/runtime/deepseek_responses_adapter.py` — DeepSeek Responses（同一把 key）
  - `src/scenic_cs_agent/runtime/openai_responses_adapter.py` — OpenAI Responses（选做）
  - `examples/step02_adapter/main.py` — 只调 `adapter.generate(...)`

### 为什么两个 Adapter

| | Chat Completions（DeepSeek） | Responses（DeepSeek） |
| --- | --- | --- |
| 入口 | `chat.completions.create` | `responses.create` |
| 系统提示 | `messages` 里 `role=system` | `instructions=` |
| 用户输入 | `messages` 里 `role=user` | `input=` |
| 结构化 | 多为 `json_object` / 拼进 system | 可 `json_schema` native |
| 模型示例 | `deepseek-chat` | `deepseek-flash` / `deepseek-v4-pro` |
| 本仓何时用 | 默认 `ADAPTER=deepseek` | `ADAPTER=responses`（同一 `DEEPSEEK_API_KEY`） |

两条通路共用 SYSTEM/USER，用来验证「换 Adapter 不改业务入口」。OpenAI Responses 仍保留作对照，需另配 key。

### 跑（默认 DeepSeek）

```bash
cd /Users/kaizen/Code/Self/scenic-cs-agent
uv sync
uv run python examples/step02_adapter/main.py
```

对比跑 Responses（推荐做一遍）：

```bash
ADAPTER=responses uv run python examples/step02_adapter/main.py
```

选做 OpenAI：

```bash
# .env 增加 OPENAI_API_KEY=...
ADAPTER=openai uv run python examples/step02_adapter/main.py
```

## 步骤 3 · Streaming 流式输出（先 CLI）

**目标**：Chat Adapter 把厂商 chunk 收成统一 `ModelStreamEvent`；终端边收边打字。

### 知识点（先记这几条）

- 流式 ≠ 更快推理；价值是可观察、可先出字、以后可取消
- 数据面：`text.delta`；控制面本步只有 `model.finished` / `model.usage`
- 上层不直接依赖 DeepSeek chunk 字段

### 本仓改动

- `model_types.py` 增加 `ModelStreamEvent`
- `DeepSeekChatAdapter.stream()`
- `examples/step03_stream/main.py` 默认 `MODE=stream`；`MODE=once` 对照非流式
- Responses 流式事件形状不同，本步先不实现（避免一次两套）

### 跑

```bash

# 对照整段：
MODE=once uv run python examples/step03_stream/main.py
```
