## 原系统在干什么（不是聊天退款）

面向**景区供应商运营群**的退款确认自动化：

1. **客服后台一键发起** → 创建退款工单  
2. **交互卡片推到供应商群**（@ 负责人白名单）  
3. 供应商点 **同意 / 拒绝**（拒绝必须填原因）  
4. 回调校验：**白名单 + 幂等**（非 PENDING 不可重复点）  
5. **同意 ≠ 立刻退款**：回到客服复核金额 → 再调退款接口  
6. 金额超阈值 → 标记需额外审批  
7. **超时升级**：2h 提醒 / 4h 升客服主管 / 8h 升运营（SLA）  
8. **台账审计**：工单各字段落盘（可切多维表格）

### 状态机（原样）

```
PENDING（待供应商确认）
  ├─ reject(+原因) → REJECTED → 写回订单后台 → CLOSED
  └─ approve → APPROVED（待客服复核）
        └─ confirmAndRefund → [金额>阈值则审批标记]
              → REFUNDING → REFUND_SUCCESS | REFUND_FAILED → CLOSED
```

### 关键字段

| 字段 | 含义 |
| --- | --- |
| work_order_id | 工单号（幂等键，如 WOxxxxxxxx） |
| supplier_id | 供应商，如 S001 |
| order_no | 订单号，如 ORD-1001 |
| amount | 退款金额 |
| reason | 发起原因（如「游客天气原因退票」） |
| creator_open_id | 发起客服 |
| operator_open_id | 点卡片的供应商负责人 |
| status | 上表状态 |
| reject_reason / approval_required / refund_* | 结果与审计字段 |

### 资金与安全红线（后续工具治理必须守住）

- 模型 / Agent **不能**直接当退款开关；同意后仍要客服复核  
- 非白名单操作人 → unauthorized  
- 同一工单重复点击 → conflict  
- 退款接口以 `work_order_id` 幂等  
- 金额阈值 demo：`5000`（超则 `approval_required`）

## 业务加厚（2026-10-30 用户确认）

在原 Java 状态机之上增加下列规则，供 Agent 工具与结构化决策使用。**仍是练习扩展**，不声称生产已上线。

### 1. 退款类型：全额 / 部分

| refund_type | 规则 |
| --- | --- |
| `full` | amount 必须等于订单可退余额（Mock 订单有 `paid_amount` / `refunded_amount`） |
| `partial` | `0 < amount < 可退余额`；须填 `partial_reason`（如改期差价、单人退） |

工具：`create_work_order` 增加 `refund_type`；非法组合 → 结构化校验失败，不建单。

### 2. 拒因分类（供应商拒绝时）

拒绝原因不能只是自由文本，须带枚举 + 说明：

| reject_code | 含义 |
| --- | --- |
| `POLICY_DENY` | 政策不允许（过期/不可退产品） |
| `EVIDENCE_INSUFFICIENT` | 材料不足 |
| `AMOUNT_DISPUTE` | 金额有争议 |
| `ALREADY_USED` | 已核销/已使用 |
| `OTHER` | 其他（说明必填且 ≥10 字） |

拒绝写回订单后台时同时带 `reject_code`。Agent 可据此建议客服下一步（补材料 / 改金额 / 转人工）。

### 3. 超时催办话术（只起草，不伪造已发送）

`scan_timeout` 结果映射动作：

| 龄期 | 动作 | Agent 可做 |
| --- | --- | --- |
| ≥2h | 提醒供应商 | 起草催办文案 + @owners；工具 `draft_remind`（不直接发，或需确认） |
| ≥4h | 升级客服主管 | 起草升级摘要（工单/金额/龄期） |
| ≥8h | SLA 违约升运营 | 标记 `sla_breached`，建议转人工专项 |

### 4. SOP / 政策答疑（本地假知识库）

`docs/sop/` 放 3～5 条 Markdown（天气退、部分退规则、白名单说明、大额审批）。  
工具：`search_sop(query)` → 返回片段；答疑时必须引用片段，禁止空口编政策。

### 5. 大额审批分支

- 阈值沿用 Java：`amount > 5000` → `approval_required=true`
- Agent 决策枚举增加 `request_approval`；`confirm_refund` 在未审批通过前 Runtime 拦截
- 练习用文件版 ApprovalStore（一步领取、参数摘要绑定 work_order_id+amount）

### 对后续 12 步的影响

- 步骤 5 `RefundDecision` 纳入 `refund_type` / `reject_code` / `request_approval`
- 步骤 6–8 工具集：`search_order`、`create_work_order`、`query_work_order`、`search_sop`、`draft_remind`、`confirm_refund`（高风险）
- 步骤 10–11 完成条件含「部分退字段齐全」「大额须审批证据」
